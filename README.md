# expansivemodelling

Reproducible motor traffic AADT estimation across the Leeds Local Authority
District (`E08000035`) with [AequilibraE](https://www.aequilibrae.com/) and open
network-cleaning tools, validated against Department for Transport (DfT) Annual
Average Daily Flow (AADF) counts.

The starting baseline is the AequilibraE assignment configuration (`aon` and
`ue_bfw` variants) from the
[aadtbench](https://github.com/Robinlovelace/aadtbench) benchmark (`leeds-v1`
case). Building on that baseline, this repository quantifies the topological,
computational, and predictive gains of multi-stage OpenStreetMap (OSM) network
cleaning and attribute fusion using open Rust tools developed in the
[csis](https://github.com/Robinlovelace/csis) ecosystem.

## Aims

1. **Central Leeds motor traffic AADT estimate**: Generate a link-level estimate
   of daily motor traffic (`motor`, plus `car`/light-motor and `heavy`
   sub-classes) across the Leeds LAD road network (`data/processed/leeds_lad_aadt.parquet`).
2. **Quantify the benefit of network cleaning**: Compare five progressive
   representations — unfiltered raw OSM (`N0`), motor-filtered raw OSM (`N1`),
   minimal Python topological cleaning (`N2`), full `csis` Rust graph cleaning
   and lane/speed welding (`N3`), and modal-filter-severed strategic motor
   network (`N4`) — across link counts, network length, connectivity, runtime,
   count-site accuracy, and network-wide vehicle-kilometres.
3. **Open vs proprietary ecosystem comparison**: Document how open tools
   (`AequilibraE`, `osmget`, `osmactive`, `netfit`/`netclean`, `netweld`,
   `countsget`) compare against closed strategic assignment suites such as
   SATURN ([Feature comparison](features_table.qmd)).

## Repository layout

- [`paper/index.qmd`](paper/index.qmd) — Camera-ready Quarto paper with
  reproducible Python chunks reading committed Parquet caches in
  `data/processed/`.
- `paper/figs/` — Publication figures generated by `scripts/04_make_figures.py`.
- [`features_table.qmd`](features_table.qmd) — Feature comparison of open vs
  closed motor traffic modelling tools.
- `scripts/` — End-to-end Python build pipeline:
  - `scripts/01_prepare_counts.py` — Normalises `countsget` DfT AADF tables,
    computes Leeds LAD Major Road Network VKM reference totals, and assigns
    5-fold 3 km spatial cross-validation blocks.
  - `scripts/02_clean_networks.py` — Builds the five network cleaning variants
    (`N0`–`N4`) using Python (`geopandas`/`scipy`/`shapely`) and the `csis`
    Rust toolchain (`osmget`, `osmactive`, `netfit`/`netclean`, `netweld`).
  - `scripts/03_run_assignments.py` — Runs the AequilibraE assignment matrix
    (`aon`, `ue_bfw`, multi-class SRN-cordon `ue_improved`, and spatially
    blocked `csis`-style calibration), stepwise ablation, and DfT validation.
  - `scripts/04_make_figures.py` — Renders all five figures under `paper/figs/`.
- `data/` — Committed inputs (`leeds-lad.geojson`, `data/dft/*.parquet`) and
  compact processed caches (`data/processed/*.parquet`, `< 10 MB` total).
- `.github/workflows/site.yml` — Renders and deploys the Quarto website to
  GitHub Pages on push.

## Reproducing the results

### 1. Fast Quarto site render (from committed caches, < 1 minute)

All summary tables, inline metrics, and figures in [`paper/index.qmd`](paper/index.qmd)
can be rendered directly from the committed Parquet caches in `data/processed/`
without requiring external datasets or local Rust binaries:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt jupyter tabulate

QUARTO_PYTHON=.venv/bin/python quarto render
```

Rendered HTML outputs are written to `_site/index.html` and
`_site/paper/index.html`.

### 2. Full end-to-end pipeline rebuild (~2.5 minutes on 32 threads)

Rebuilding `data/processed/*.parquet` and `paper/figs/*.png` from raw OSM and
synthetic OD inputs requires:

1. Local checkout of the [`aadtbench`](https://github.com/Robinlovelace/aadtbench)
   `leeds-v1` benchmark case at `~/github/robinlovelace/aadtbench/cases/leeds-v1/`.
2. Release binaries of the open Rust network toolchain:
   - [`osmget`](https://github.com/Robinlovelace/osmget) (`target/release/osmget`)
   - [`osmactive`](https://github.com/atf-lab/osmactive) (`target/release/osmactive` + `rules/gb.toml`)
   - [`netfit`](https://github.com/atf-lab/netfit) / `netclean` (`target/release/netfit`)
   - [`netweld`](https://github.com/atfutures/netweld) (`target/release/netweld`)

Run the four numbered pipeline scripts in order, then render the Quarto site:

```bash
source .venv/bin/activate
python scripts/01_prepare_counts.py
python scripts/02_clean_networks.py
python scripts/03_run_assignments.py
python scripts/04_make_figures.py

QUARTO_PYTHON=.venv/bin/python quarto render
```

## Data inputs and tool attributions

| Component | Source / Repository | Path / Role |
|---|---|---|
| Leeds LAD boundary | ONS Open Geography Portal (`E08000035`, OGL v3.0) | `data/leeds-lad.geojson` |
| DfT AADF traffic counts | DfT Road Traffic Statistics via [`countsget`](https://github.com/atf-lab/countsget) (OGL v3.0) | `data/dft/*.parquet` |
| Raw OSM & synthetic OD | [`aadtbench`](https://github.com/Robinlovelace/aadtbench) `leeds-v1` case (ODbL 1.0) | `cases/leeds-v1/` |
| PBF highway & barrier ingest | [`osmget`](https://github.com/Robinlovelace/osmget) | `scripts/02_clean_networks.py` |
| UK modal access & modal filters | [`osmactive`](https://github.com/atf-lab/osmactive) (`rules/gb.toml`) | `scripts/02_clean_networks.py` |
| 14-stage graph consolidation | [`netfit`](https://github.com/atf-lab/netfit) (`netclean` crate) | `scripts/02_clean_networks.py` |
| Lane & speed limit conflation | [`netweld`](https://github.com/atfutures/netweld) | `scripts/02_clean_networks.py` |
| Equilibrium assignment | [AequilibraE](https://www.aequilibrae.com/) (BFW User Equilibrium) | `scripts/03_run_assignments.py` |
